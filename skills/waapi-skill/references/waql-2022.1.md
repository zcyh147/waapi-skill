## Syntax

WAQL returns a sequence of Wwise objects. A query chains a source and optional transforms, where one sequence feeds the next. In Wwise UI search fields, a WAQL query uses the `$` prefix. In WAAPI `ak.wwise.core.object.get`, the `waql` argument is a string and examples show payloads with or without `$`.

Supported source forms from the cited docs:

- `from project`, all objects in the Wwise project.
- `from object OBJECT_SPECIFIER`, objects by path, GUID, qualified unique name, or ID. The docs also allow shorthand by typing the path, GUID, or qualified name directly.
- `from type OBJECT_TYPE`, objects of a Wwise type, such as `Sound`, `Event`, `RandomSequenceContainer`, or `Bus`.
- `from search "TEXT"`, toolbar-style text search across object names and notes.
- `from query QUERY_SPECIFIER`, results from a pre-existing Wwise Query.

If a source is omitted, the query starts from all objects in the project.

## Operators

Documented `where` operators and expression tools:

- `=` and `!=` compare strings, numbers, or booleans. String comparison is case-insensitive.
- `<`, `<=`, `>`, and `>=` compare numeric values.
- `:` does word or partial string matching and supports `*` wildcards.
- `= /REGEX/` matches strings with an ECMAScript regular expression.
- `and`, `or`, `!`, and parentheses combine, negate, and group boolean expressions.
- `.` chains object expressions and property/reference access, for example `parent.name` or `maxRadiusAttenuation.radius`.

Documented transforms:

- `select children`, direct children.
- `select descendants`, recursive children.
- `select this`, the current object.
- `select parent`, direct parent.
- `select ancestors`, recursive parents.
- `select referencesTo`, objects referencing the current object.
- `select owner`, owner of custom objects defined inside other objects.
- `skip COUNT`, skip items.
- `take COUNT`, keep a count of items from the start of the sequence.
- `orderby VALUE_EXPRESSION` and `orderby VALUE_EXPRESSION reverse`, sort ascending or descending.
- `distinct`, keep unique objects only.

## Object model

WAQL works over Wwise objects and Wwise object types. Cited examples include `Sound`, `Event`, `RandomSequenceContainer`, and `Bus`.

Built-in accessors are case-insensitive. NotebookLM cited these examples from the source docs:

- identity and naming: `id`, `name`, `notes`, `path`, `filePath`
- type information: `type`, `classId`, `category`
- state: `isPlayable`, `isExplicitMute`, `isExplicitSolo`, `isImplicitMute`, `isImplicitSolo`, `isIncluded`
- hierarchy: `childrenCount`
- media and audio: `pluginName`, `convertedFilePath`, `activeSource`
- computed audio data: `maxDurationSource.id`, `maxDurationSource.trimmedDuration`, `maxRadiusAttenuation.id`, `maxRadiusAttenuation.radius`

Property and reference access:

- No prefix returns the effective value used at playback, including override/inheritance resolution.
- `@PROPERTY` or `@REFERENCE` returns the value directly set on the object, ignoring the override system.
- `@@PROPERTY` or `@@REFERENCE` returns the effective value and is required when a property name conflicts with a built-in accessor.

## Escaping

Documented escaping rules:

- WAQL object paths, GUIDs, and string literals are enclosed in double quotes.
- Regex literals are enclosed in forward slashes without double quotes, for example `/^My/`.
- When WAQL is sent through WAAPI JSON, normal JSON string escaping applies.
- Wwise path backslashes must be escaped for JSON, for example `"\\Actor-Mixer Hierarchy\\Default Work Unit"` in JSON text represents the WAQL path `"\Actor-Mixer Hierarchy\Default Work Unit"`.
- Double quotes required inside a JSON string must be escaped, for example `{ "waql": "from search \"Tone\"" }`.

## Results

WAQL executes through `ak.wwise.core.object.get` by passing the `waql` string in the arguments object. The WAAPI response is a JSON object with a `return` key. That key contains an array of matched objects.

The `options` object can include a `return` array that controls the fields in each returned object. The docs show built-in accessors, properties, and references, including prefixed properties such as `@Volume`. If no return array is supplied, NotebookLM cited the default as `['id', 'name']`. If a requested property is incompatible or missing on an object, it is omitted from that object's result.

The generated 2022.1 manifest agrees with this inventory: `ak.wwise.core.object.get` has an args schema with a `waql` string, legacy `from`, legacy `transform`, and an options schema referencing object return options. Its result schema contains `return`, an array of Wwise object return records.

## Examples

Live-safe examples that only read project state:

```json
{
  "uri": "ak.wwise.core.object.get",
  "args": {"waql": "from type Sound"},
  "options": {"return": ["id", "name", "type"]}
}
```

```json
{
  "uri": "ak.wwise.core.object.get",
  "args": {"waql": "from search \"Tone\" where category = \"Actor-Mixer Hierarchy\""},
  "options": {"return": ["id", "name", "path"]}
}
```

```json
{
  "uri": "ak.wwise.core.object.get",
  "args": {"waql": "\"\\Actor-Mixer Hierarchy\" select descendants where name = /^My/"},
  "options": {"return": ["id", "name", "path"]}
}
```

```json
{
  "uri": "ak.wwise.core.object.get",
  "args": {"waql": "from type Sound where @Volume < 0"},
  "options": {"return": ["id", "name", "@Volume"]}
}
```

Legacy JSON query support exists but is discouraged by the cited docs. Use `waql` for helper generation.

## Limitations

Documented limitations and cautions:

- The legacy JSON `from` and `transform` query format is still supported but discouraged because WAQL has more functionality, better error handling, and is easier to use.
- The 2022.1 release notes mention a prior WAQL limitation fixed in 2022.1.9: `isIncluded` was added or fixed to correctly consider the Inclusion property of ancestor objects.
- The sources did not document WAQL execution timeout thresholds, memory limits, recursion limits for `descendants` or `ancestors`, or pagination guidance beyond the legacy `range` transform.
- The sources did not provide the JSON schema for WAQL compilation or syntax errors returned through WAAPI.
