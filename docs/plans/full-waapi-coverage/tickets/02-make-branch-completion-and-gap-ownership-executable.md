## What to build

The coverage checker explains exactly which native-supported uses are unavailable or unverified, which implementation ticket owns each gap, and whether the overall effort is actually complete.

## Acceptance criteria

- [ ] Independently enumerate inputs, results, enums, unions, collections, optional/default distinctions and reachable shared definitions across all native hosts and versions; add meaningful target, placement and operation-mode distinctions.
- [ ] Map each branch to a public contract and route, exact construction/validation behavior, appropriate verifier and candidate-scoped required evidence. Whole-family attribution, parent mappings and test-definition filenames do not establish descendant completion.
- [ ] Evaluate actual projected read and multi-call business/transaction observations, not only a zero-input ping envelope. Tie each alternative, presence/default and collection assertion to the exact observed field; an unrelated field or parent PASS cannot satisfy it.
- [ ] Use reviewed per-branch evidence requirements and sealed relevant-source/native-shape/host/behavior equivalence for reusable evidence. Consume the established native category and ScenarioLifecycle metadata producer formats with positive compatibility and tampering tests. Missing formal Fresh archive integration stays unverified and is implemented under #194; no label-only Fresh credit or automatic rerun budget is allowed.
- [ ] Assign every in-scope record to a functional ticket in this specification. Any new or oversized gap must produce a bounded same-parent implementation child and a blocking edge to final acceptance before its discovery work is considered resolved. Final acceptance is not a catch-all implementation owner.
- [ ] Compute unresolved, missing implementation, implemented-unverified, environment-blocked, verified, proven-native-absence and approved-exclusion states from evidence. Replace the fixed incomplete response; retain a separate reproducibility result.
- [ ] Demonstrate a complete controlled example and fail completion after removing a branch, version, enum, public route, mapping or required evidence, substituting a same-count URI, or mislabeling missing Skill support as native absence. This tool ticket may finish while correctly reporting an incomplete product.
- [ ] Account explicitly for Wwise 2021.1, 2022.1, 2023.1, 2024.1 and 2025.1, with exact host/build provenance and applicable native shapes. A current packaged boundary is not proof of native absence.
- [ ] Maintain exact owned branch IDs, public input/routing, construction, result/verification alternatives and required evidence, including reachable shared definitions and newly discovered variants. In-scope omissions must be implemented here or split into linked same-parent implementation children; they never leave the overall scope.
- [ ] Verify the highest existing public Gateway seam with positive and meaningful negative controls. Use sequential owned native tests where behavior needs native proof; preserve source projects and original evidence. No Fresh run is authorized until a separate exact budget is approved.
- [ ] Preserve Gateway-owned request construction, configuration binding, the three modification policies, immutable Preview, execute-once semantics and truthful uncertainty. Do not add a raw-input escape or weaken safety to claim coverage.
