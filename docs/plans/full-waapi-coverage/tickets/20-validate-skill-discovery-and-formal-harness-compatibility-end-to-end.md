Preserve original verdicts and any separately justified business assessment; reject program/native receipts merely relabeled as Fresh. This implementation belongs here, while the approved small Fresh budget remains separate.
- [ ] Produce the smallest justified Mac-only Fresh selection by distinct interaction mechanisms, listing cases, turns, transactions, model settings and maximum attempts for explicit approval. No Fresh run or automatic retry is authorized by this ticket draft.
- [ ] Account explicitly for Wwise 2021.1, 2022.1, 2023.1, 2024.1 and 2025.1, with exact host/build provenance and applicable native shapes. A current packaged boundary is not proof of native absence.
- [ ] Maintain exact owned branch IDs, public input/routing, construction, result/verification alternatives and required evidence, including reachable shared definitions and newly discovered variants. In-scope omissions must be implemented here or split into linked same-parent implementation children; they never leave the overall scope.
- [ ] Verify the highest existing public Gateway seam with positive and meaningful negative controls. Use sequential owned native tests where behavior needs native proof; preserve source projects and original evidence. No Fresh run is authorized until a separate exact budget is approved.
- [ ] Preserve Gateway-owned request construction, configuration binding, the three modification policies, immutable Preview, execute-once semantics and truthful uncertainty. Do not add a raw-input escape or weaken safety to claim coverage.

- [ ] Prove that the declared larger closed-layout constructor terminal response is delivered intact through the existing deterministic Gateway/Broker/archive chain before spending Fresh quota. Candidate `3e7b0b7a` emits roughly 264 KiB for accepted near-limit requests under a narrow 280 KiB ceiling while retaining exact `agent_result`; CLI byte-fit tests alone do not prove broker or Agent delivery. Test complete Unicode/escaped payloads, terminal state and exact final machine result. If the existing chain truncates or rejects them, implement a compatible bounded delivery contract in this project instead of counting a local stdout pass as acceptance. Ordinary responses retain their compact budget.

- [ ] Repair the formal harness routing and durable-event taxonomy for the public `draft-declare-layout-plan` command. Reproduce the current closed Draft protocol rejection and original `settings.revised` audit mismatch, then accept the exact Gateway-issued layout declaration through the existing authenticated Broker and original Draft/archive replay. Preserve authority/revision bindings, exact audit-event checks and canonical request seals; reject missing/changed events and corrupted output. Combine this with the existing near-capacity layout output delivery criterion; do not introduce another harness or treat synthetic payload transport as full Gateway/Fresh acceptance.

- [ ] Audit every public Draft command against the existing formal Broker and durable archive event policy. Cover the actual `settings.revised` producers `draft-declare-cli-console-plan`, `draft-declare-debug-intent`, `draft-declare-host-plan`, `draft-declare-layout-plan`, `draft-declare-soundengine-plan` and `draft-declare-undo-plan`; preserve `draft-start-undo-child` as a separately bound child-record lifecycle, `draft-inspect` as a successful read with unchanged revision/audit, and `draft-apply` as the typed-action lane. Require each applicable command to have an exact event mapping or an explicit tested separate-lane/no-event policy, with original per-Draft records, authority/revision bindings and corruption controls. Unknown commands/events remain rejected; no blanket allowlist or generic ignored-event fallback.
