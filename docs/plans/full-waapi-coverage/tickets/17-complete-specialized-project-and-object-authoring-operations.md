# 17: Complete specialized project and object authoring operations

Status: draft for user review; not yet published or authorized for implementation.

## Parent

[Complete WAAPI business coverage across Wwise 2021.1–2025.1](https://github.com/zcyh147/waapi-skill/issues/174).

## What to build

Users can perform the native-specific authoring operations that generic object edits cannot faithfully substitute, with all legal parameters and meaningful target variants.

## Acceptance criteria

- [ ] Own dedicated Core authoring concepts including attenuation/RTPC curves, randomizers, State and Switch relationships, blend assignments/tracks, active sources, GameParameter range edits, property transfer and other exact assigned specialized contracts.
- [ ] Map every legal enum, point/row shape, mode, target relationship, platform alternative and omitted/default behavior to a closed business request with disclosed choices.
- [ ] Apply shared property/dependency semantics and expose necessary derived changes in Preview; do not force a generic property workaround or inherit generic object-operation PASS.
- [ ] Independently verify requested specialized state, relationships and preservation; creation, editing and runtime value-setting remain distinct routes.
- [ ] Test invalid curve endpoints/shape choices where applicable, wrong target type, stale related objects, unsupported native modes and partial effects. Large exact contract sets must split into bounded same-parent children, not become deferred work.
- [ ] Account explicitly for Wwise 2021.1, 2022.1, 2023.1, 2024.1 and 2025.1, with exact host/build provenance and applicable native shapes. A current packaged boundary is not proof of native absence.
- [ ] Maintain exact owned branch IDs, public input/routing, construction, result/verification alternatives and required evidence, including reachable shared definitions and newly discovered variants. In-scope omissions must be implemented here or split into linked same-parent implementation children; they never leave the overall scope.
- [ ] Verify the highest existing public Gateway seam with positive and meaningful negative controls. Use sequential owned native tests where behavior needs native proof; preserve source projects and original evidence. No Fresh run is authorized until a separate exact budget is approved.
- [ ] Preserve Gateway-owned request construction, configuration binding, the three modification policies, immutable Preview, execute-once semantics and truthful uncertainty. Do not add a raw-input escape or weaken safety to claim coverage.
