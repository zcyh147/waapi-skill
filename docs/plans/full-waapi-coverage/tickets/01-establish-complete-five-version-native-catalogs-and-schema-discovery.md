# 01: Establish complete five-version native catalogs and schema discovery

Status: draft for user review; not yet published or authorized for implementation.

## Parent

[Complete WAAPI business coverage across Wwise 2021.1–2025.1](https://github.com/zcyh147/waapi-skill/issues/174).

## What to build

A maintainer can inspect the complete independently evidenced Console and in-scope Authoring capability set through versioned discovery, with missing wrapper support reported separately from missing native support.

## Acceptance criteria

- [ ] Reuse retained five-version Authoring URI inventories and exact schema evidence; record build, host, session, source digest and referenced definitions. Collect only missing or insufficiently attested facts through controlled public read paths, opening matching Authoring versions sequentially when necessary.
- [ ] Include at least the currently known 23 ordinary Authoring schema rows on 2024.1 and 25 on 2025.1, and any additional differences found. Check shared Console/Authoring schema parity instead of assuming parity from matching URI names.
- [ ] Keep the two excluded Authoring Lua/launch additions visible as approved exclusions. Do not remove existing public Core/CLI Lua capabilities or broaden a narrow direct-client collection exception.
- [ ] Make collected schema truth available through existing offline Gateway catalog/schema discovery without claiming that an unimplemented execution route is ready. Preserve live host detection and config-only connection identity.
- [ ] Prove missing schemas, unresolved definitions, wrong host/build, changed digests and same-count URI substitutions are detected. Preserve source-project integrity and distinguish raw reflection from business execution evidence.
- [ ] Account explicitly for Wwise 2021.1, 2022.1, 2023.1, 2024.1 and 2025.1, with exact host/build provenance and applicable native shapes. A current packaged boundary is not proof of native absence.
- [ ] Maintain exact owned branch IDs, public input/routing, construction, result/verification alternatives and required evidence, including reachable shared definitions and newly discovered variants. In-scope omissions must be implemented here or split into linked same-parent implementation children; they never leave the overall scope.
- [ ] Verify the highest existing public Gateway seam with positive and meaningful negative controls. Use sequential owned native tests where behavior needs native proof; preserve source projects and original evidence. No Fresh run is authorized until a separate exact budget is approved.
- [ ] Preserve Gateway-owned request construction, configuration binding, the three modification policies, immutable Preview, execute-once semantics and truthful uncertainty. Do not add a raw-input escape or weaken safety to claim coverage.
