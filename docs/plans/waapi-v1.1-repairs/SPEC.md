# WAAPI v1.1 使用问题修复规格

日期：2026-10-17。调查基线：f633403a。状态：用户已批准规格与任务拆分。
已批准发布规格和任务；本次仅建立工作队列，不启动实现或测试。

## Problem Statement

用户通过 Skill 完成 Wwise 工程工作时，遇到连接覆盖丢失、属性无法完整列出、发现结果超限、合法依赖被拒绝、新对象依赖字段无可执行下一步、ShareSet 创建用错拓扑，以及正式结果夹带删除测试工程的提示。原有“任何错误都停止”规则让无副作用查询也反复请求批准。“API 有入口”的证据不足以证明所有业务分支已支持。

## Solution

正常操作统一读取用户配置，连接身份贯穿草稿和事务。提供列属性、查准确详情、选择 Field Handle 的直接路径及分页。补齐已知条件依赖和创建分支。在三种修改模式内允许合理继续，保留不可盲目重复写入的约束。正式操作保留用户工程，测试资源由测试运行器管理。通过反射对账和业务组合审计找出其他漏项。

## User Stories

1. 作为用户，我希望一次配置端口和版本，之后所有命令都使用它们。
2. 作为用户，我希望配错版本或换了项目时，Gateway 在业务操作前拒绝继续。
3. 作为用户，我希望 CLI 重启后，旧草稿不会转去另一个工程。
4. 作为 Agent，我希望列出插件的实际属性，而不是只能猜搜索词。
5. 作为 Agent，我希望选择返回的准确属性，读取类型、范围、选项、依赖、RTPC 支持和已知单位。
6. 作为 Agent，我希望大列表可以翻页，完整性和剩余内容清楚可见。
7. 作为用户，我希望给声音关联衰减时，必要定位设置在变更预览中明确出现。
8. 作为用户，我希望创建 GameParameter 并设置范围、默认值，有明确可完成的流程。
9. 作为用户，我希望新对象配置未完成时，不被报告为整个任务成功，也不被重复创建。
10. 作为用户，我希望明确区分给 Sound 添加效果与创建独立 Effect ShareSet。
11. 作为用户，我希望不合适的创建目标在写入前被拒绝。
12. 作为用户，我希望只读查询失败后 Agent 可以调整查询，不再额外请求批准。
13. 作为用户，我希望既有修改模式继续决定授权，而不是每类普通错误再增加审批。
14. 作为用户，我希望结果不确定的写操作先被核实，不被盲目重放。
15. 作为用户，我希望正式工程和产物不会收到测试用的丢弃或隔离指令。
16. 作为维护者，我希望每个业务分支都有公开契约、实现和独立证据，而不是只统计 URI 数量。
17. 作为维护者，我希望主要依赖确定性测试，Fresh Agent 只验证无法由程序证明的使用行为。

## Implementation Decisions

### 配置及连接

- 正常在线业务操作的地址、端口和预期版本统一来自所选配置文件；配置修改仍通过 config-set。
- 普通业务命令不接受临时连接 flags 或连接环境变量覆盖。独立副本须明确使用独立配置文件；仅复制 Skill 目录不会自动隔离现有用户级配置。
- 离线多版本 schema 浏览与在线连接配置分离，保留开发目录查询能力。
- Operation Draft 在硬盘记录初始连接配置；首次 live 验证补全项目 GUID、版本/build。Change Preview 和事务保存相同身份约束。
- 后续调用先读取所选配置，与原记录比较；发生变化则明确拒绝，既不静默转向新工程，也不偷偷沿用用户已经更改的目标。真实 getInfo 和项目身份仍需检查。
- 无 Draft 的查询、inline/zero-input 操作及其他公开入口同样只走配置。已有草稿若缺少新绑定字段，返回明确兼容边界，不猜历史连接。
- allow_changes 仍经过参数准备、Preview、授权绑定和验证，不绕过 Draft 或事务。

### 元数据及分页

- 新增公开属性列表和准确详情契约；命令拼写在实现时通过现有路由确定。
- 选择来自 Gateway 返回的作用域绑定标识，不开放任意 native args/options。准确属性名称可展示；修改继续使用 Field Handle。
- 详情保留底层支持的单位、类型、默认值、约束、枚举、依赖及 RTPC 支持。缺单位明确未知。
- 文字发现为辅助。精确匹配在输出投影和大小检查前收窄；列表分页、详情按需读取。
- 分页标识绑定对象/类、版本和元数据快照；顺序稳定，过期或作用域改变明确拒绝；标识不授予修改权限。无法装入单页的单项详情须有受控分段读取或明确可定位边界，不静默截断。
- 修复候选被拒绝后只剩无关结果的问题，返回有界、逐字段的原因。
- 遵守现有 Business Declaration/Field Handle 边界；如最终准确选择语法调整了现有 ADR，用显式 ADR 更新记录，不偷偷恢复 raw API 输入。

### 条件依赖及新对象

- 实现现场出现的条件依赖结构，重复依赖去重，冲突/未知结构明确拒绝。必要属性变化归入同一可见 Preview 并独立读回。
- GameParameter 先做确定性沙盒验证：若 Wwise 支持创建时配置，支持相应新对象验证；否则提供明确分阶段流程。分阶段各有独立 Preview/授权/验证，不宣称整体原子性，不在 Preview 之后追加隐藏写入。
- 中断/部分成功不重复创建，已完成步骤以现有事务和对象证据识别；不新建跨会话恢复体系。

### 插件创建

- 公开区分 owner effect instance 与独立 Effect ShareSet。
- ShareSet 使用经版本验证的 Work Unit children 创建结构、现场 Type Handle 和插件类型；不是把 Work Unit 当效果槽 owner。
- 目标类型/位置和插件可用性在写入前检查；独立解析和验证 ShareSet 父对象、插件类型、名称、参数；保留现有效果槽路径。

### 错误后继续与清理

- 三种已有修改模式是权限来源，普通查询、翻页、搜索修正及有限重连不增加审批。
- 根据失败阶段、是否已派发写入、状态证据给出可执行后继；启动服务仍须在原任务授权范围内。
- indeterminate 可在模式与授权允许时独立只读诊断，原写事务不重放。结果未知不能报成功，也不能凭错误字符串保证未修改。
- 清理配对资源（如 transport）与删除测试工程是不同职责；前者保留，后者只在测试生命周期管理器中执行。
- 用户工程和输出默认保留。审计 import/replace/generate 等所有公开输出，不把“不可逆”转换为删除工程的指令。

### 全分支覆盖审计

- 使用五版本 Console 反射、窄 Authoring overlay、执行分区、命名操作、非命名路由及 Topic 契约生成逐行清单。
- 对 schema 的属性、enum、联合分支、嵌套集合、optional 语义与公开输入映射做机械对账；再加入来源明确的业务组合（目标类型、放置位置、操作模式、版本差异）。不穷举无意义的参数笛卡尔积。
- 每行记录来源、公开 schema、编译入口、前置边界、验证器、程序证据、真实证据及状态。实现与证据分开，未知项不算完成。
- 追查 ShareSet 在旧清单中的位置、状态及完成依据；区分需求遗漏、映射误判、测试只覆盖一个用法等原因，以历史证据结论为准。
- 审计新增大项单独列为待排期，不自动扩展本轮实现；不以降级为禁止来掩盖原要求漏项。

## Testing Decisions

首选最高已有测试入口：真实 Gateway parser/execute_gateway + FakeClient + 隔离配置/状态目录，覆盖公开调用至验证结果，断言用户结果和无额外副作用。编译器/分页等纯函数仅作补充，不重复镜像实现。

- 开发：运行受影响的现有程序测试，经仓库测试入口使用 Poetry。
- 合并候选：固定五版本 Program 和完整 Non-live 各完成一次；后续仅在变更或失败需要时重跑。
- 真实 Wwise：确定性 Python 测试使用现有沙盒生命周期，顺序运行。优先 2025.1；2022.1 插件差异等按证据补测。任何声称支持的新增分支须给出版本证据或明确未验证边界，不拿 fake tests 冒充 real PASS。
- Fresh：仅 Mac，首轮四个工作流，各一次，不乘五版本。使用现有正式 Fresh CLI harness，独立内存隔离、冻结同一候选、新 campaign root；默认 gpt-5.6-terra / medium / default。主版本拟为 2025.1，最终在花费前固定。
- 四个工作流：F1 属性列表/分页/详情及插件配置；F2 普通无匹配后的自主继续；F3 创建 GameParameter 并配置；F4 创建独立 ShareSet。每项可多用户回合、可多个分别预览的事务，准确记录调用数和费用，不把“四个工作流”说成四次模型请求。
- 已知成本先用静态 fixture 和确定性 live tests 消化；使用可用且无需额外许可证的测试插件，Mastering Suite 许可失败不触发昂贵反复尝试。
- 完成冻结首轮再分类修复普通失败；系统性沙盒/证据故障立即停。最多首轮四个 Fresh 工作流，额外 Fresh/重跑先说明必要性与运行数并取得用户批准。不得静默启动 screening/full matrix。
- 业务结果独立证明、授权正确且仅轻微措辞差异时，保留 raw verdict 并写业务评估，不为了全绿反复试。失败记录不改写，只有原全 PASS root 才做相同选项 verify-only。
- Windows 本轮不做 Fresh、不宣称 Windows 实机验收。纯代码可以模拟 Windows 输入，但不能据此声称原生传输已验证。将未执行的 Windows 检查记录为验证范围，而不是推定与 Mac 相同。

## Out of Scope

修复 Lyra 正式工程、使用现场草稿/事务重放；自动删除任何用户/失败证据目录；恢复原始 native 请求公开入口；插件不存在的功能及许可证处理；新增 Wwise 版本；全量 Fresh/五版本真实矩阵；所有审计新漏项自动实现；最大距离、点距和 LPF 声学效果专项修复。

## Further Notes

规格和任务已获用户批准；发布阶段不修改代码、ADR、测试判定或版本资产。主要历史事实来自本线程及 Lyra gateway-output；现场脚本完成不算 Skill 验收。曲线枚举披露已由 v1.1 修复，仅作回归，不重复开发。GitHub 是正式 tracker；发布时保留原历史证据。
