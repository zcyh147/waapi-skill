Strict real modes are `live`, `destructive`, `smoke`, and `matrix`. `all` is a composite runner: it executes non-live first, then the strict real matrix. Strict real modes require an executable `WWISE_CONSOLE` and an existing `.wproj` at `WWISE_SAMPLE_PROJECT_PATH`; these can come from environment variables or the untracked `tests/fixtures/local/live-environment.json` test config (template: `tests/fixtures/local/live-environment.example.json`, override path: `WWISE_TEST_CONFIG`). Missing prerequisites fail before pytest execution. `ready_duration_seconds` measures WAAPI readiness, not the total foreground GUI or plugin warning lifetime.

Fresh Codex v2 is the formal semantic workflow documented in `tests/semantic/README.md`. The campaign wrapper freezes the Skill, suite, harness, live config, Codex binary, interpreter, and immutable options; dispatches the v2 matrix in version batches; and seals append-only attempts before consolidation or resume. It uses the Skill-local Python interpreter, a new Codex CLI process/thread/turn, and disposable `HOME` and `CODEX_HOME` for every phase. A live selection first records a no-install `waapi-client` dependency check in `live-preflight.json` and fails before Codex or WwiseConsole when the current interpreter is unsuitable; pure offline selections skip that check. The runner records memory as disabled and separates proven pre-action service/timeout/quota failures from Skill grading, while authentication and unproven runtime states are blocked. The declared 40/98/168 profile sizes are suite contracts, not claims that a formal or full run completed. OpenCode batches remain a legacy comparison lane and their archives must not be mixed into fresh Codex evidence. Mocked/nonlive pytest coverage is CI-safe but is not a live WwiseConsole validation substitute.
